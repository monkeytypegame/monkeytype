# Roadmap: replacing Chart.js with TanStack Solid Charts

Companion to `spec.md` next to this file. One row per step; each step is one PR. **All steps land on the integration branch `integration/charts`** (S1 creates it; every step's PR targets it, so each step is reviewed before it joins the branch). When the last step is in, **one move PR brings the whole branch into `master`** — the move includes the Chart.js removal (S12), so master never ships two chart libraries at once; the temporary double state exists only on the integration branch. IDs are stable so rows can reference each other. The library is `@tanstack/charts` 1.5.0; the `v1.5.0` release-source docs are the implementation reference (the live docs follow `main`).

**Size** column: S is one area, low risk, under ~150 lines; M is several files or a visible behaviour change; L is cross-cutting.

## Per-step checklist

- Definition-builder spec green for the chart (new), existing specs green unchanged (the flag defaults to Chart.js); `pnpm vitest run` on the touched areas.
- `pnpm oxlint --type-aware --type-check`, `npx oxfmt` on the diff, `pnpm lint-styles` for the scss.
- Browser parity per `docs/AGENT_BROWSER.md`: dev flag both ways — the chart, a theme change, hover/tooltip, click (where present), a window resize. Screenshots for the PR evidence.
- Production build: the new/changed modules land in `vendor-chart`; record the chunk delta (the branch temporarily carries both libraries; master only ever gets one, via S12).
- The Chart.js half of a migrated chart carries `// Stepping stone: replaced by the TanStack implementation; removed in S12`.
- Tick this row: "Done in [PR link]: <one line>" + what later rows depend on.
